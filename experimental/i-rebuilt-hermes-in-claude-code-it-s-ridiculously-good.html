1 Three Hidden Costs of Off-the-Shelf Systems ▶ 1:00

Before building, Simon identifies three costs that only show up after you're committed:

  • Cost 1: Inherited assumptions. Hermes's self-learning loop has no external guardrails — the same model that writes a skill is also the sole judge of its correctness. It can quietly overwrite your improved skills with worse versions, with no version control or audit log.
  • Cost 2: Can't fix what you don't understand. OpenClaw has 200+ vulnerabilities filed since February, including 386 malicious packages from a single threat actor on the skills marketplace. When something breaks at this scale, you're debugging someone else's code.
  • Cost 3: Doesn't scale across your business. One user spent 100+ hours and $1,000+ testing OpenClaw over 2 months only to find bugs and security gaps disqualified it. He then replicated 30% of its features in Claude Code in weeks.
"Hermes may be faster to start, but your own setup is faster to scale. The hidden costs only show up once you're already committed."

2 The Identity Layer — What Hermes Nails ▶ 4:00

Hermes uses memory.md and user.md files injected into every conversation — a simple, effective identity system. But it's designed for one individual. No concept of switching brand contexts, client contexts, or business contexts within a single install.

For multi-client work, you'd need separate Hermes installations per client, each with its own memory, skills, and learning loop — embedding a maintenance nightmare since skills aren't shared.

Simon's alternative: Same injection pattern, but with shared brand context (voice, ICP, visual identity) per client. Each client has its own context files, but skills and procedures are shared across the folder structure. One install handles multiple clients.

3 The Memory System — Three Levels ▶ 6:30

Hermes's memory system has three well-designed levels:

  1. Storage: Auto-saves and summarizes every conversation turn
  2. Injection: Important memories injected into every conversation via memory.md, user.md, and folder .md files (capped at ~1,300 tokens)
  3. Recall: Long-term memory search for information not in the recent injection

The limitation: recall searches by keyword, not meaning. If you can't remember the exact words you used with Claude 6 months ago, long-term recall becomes nearly useless.

Simon's fix: keep Hermes's injection pattern (capped memory.md for recent context) but replace keyword-based recall with semantic search via MemSearch — search by meaning, not exact words.

4 The Self-Learning Loop — Where It Gets Controversial ▶ 9:00

Hermes's biggest selling point: after finishing a task, the agent writes itself a new skill and uses it next time. Sounds brilliant — until the 10th or 20th skill.

The problem:

  • Skills accumulate: "LinkedIn post V1", "LinkedIn post V2", "LinkedIn post for this client", "LinkedIn post writer 1 and 2" — all slightly different, similar descriptions
  • The agent doesn't know which skill to use — no visibility of existing skills
  • Each skill captures the approach at that moment in time for that specific context
  • When brand voice or client positioning changes, you have 15 places to update
"Yes, it's absolutely faster to build this way initially, but it's a hell of a commitment to maintain properly and basically impossible to scale across multiple clients."

5 Skill Systems — The Modular Alternative ▶ 11:00

Simon's solution: Skill Systems instead of one-off skills.

A skill isn't a single task — it's a modular component feeding into a system. Each component does one job, lives in one place, has a consistent naming format, and gets updated in one place with changes propagating everywhere.

Example — "Write a LinkedIn post": Instead of baking voice + audience + format into one skill, you maintain them as separate skills. The LinkedIn post skill system chains them together in the right order, pulling the current version of each component.

  • Brand voice shifts? One file to update — every skill system that uses it gets the update.
  • New client? Reuse the same skill systems, just point at different context files.
  • Result: Infinitely maintainable and scalable.
"Hermes is faster to build the first skill. Building your own approach is faster to build the 10th, the 100th skill system — and infinitely easier to maintain."

6 Build vs. Buy — The Trade-Off ▶ 13:00

The core trade-off:

  • Off-the-shelf (Hermes/OpenClaw): Faster to start. You inherit their architecture, their assumptions, and their problems. When something breaks, you're debugging code you didn't write.
  • Custom build: Slower to start. You'll get some things wrong. But every layer is visible, editable, and reusable. When something breaks, you know where to look.

Neither is universally right. The question is whether you need speed-to-start or speed-to-scale.

🎯 Key Takeaways

  1. Off-the-shelf agentic systems are fast to start but inherit hidden costs — assumptions you didn't know existed, security vulnerabilities, and scaling limitations.
  2. Hermes's self-learning loop lacks external guardrails. The model grades its own homework — no version control, no audit log, and it can overwrite your improvements.
  3. Identity is single-tenant by design. Multi-client work requires separate Hermes installs with unshared skills — a maintenance nightmare.
  4. Memory injection is well-designed; long-term recall is not. Keyword search fails when you can't remember exact words from months ago — semantic search is the fix.
  5. Skills accumulate into maintenance debt. By the 20th auto-generated skill, you have 15 variants doing roughly the same thing with slightly different context.
  6. Skill Systems beat one-off skills. Modular components (voice, ICP, format) maintained in one place, chained together by skill system prompts — one update propagates everywhere.
  7. Faster to start ≠ faster to scale. Custom builds move slower initially but are infinitely more maintainable for multi-client, multi-brand operations.
  8. Understanding the architecture gives you more leverage than installing something blindly — you can fix what you understand.
