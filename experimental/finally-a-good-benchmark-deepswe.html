Overview

Matthew Berman breaks down DeepSWE, a new software engineering benchmark by DataCurve.ai that is going viral for one reason: it actually aligns with how developers use coding agents in practice. Unlike SWE-Bench Pro — which uses public commits, verbose prompts, and has an alarming 24% false negative rate — DeepSWE features handcrafted contamination-free tasks, short behavior-focused prompts, and dramatically better verification. The headline result: GPT 5.5 dominates with a 15+ point lead over Opus 4.7, at one-third the cost and half the time. This is the first benchmark where the numbers match what engineers are saying on coding Twitter.

1 The Benchmark Problem ▶ 0:00

Berman opens with the question everyone asks: "GPT 5.5 or Opus 4.7, which one is best?" The AI industry's answer should come from benchmarks, but the problem is that most benchmarks don't reflect real-world usage of the models — especially for coding.

  • Every week there's a new "best model" across the board of benchmarks, but it never quite lines up with reality
  • People end up waiting for the "vibe check" — which seems to be much more reliable than formal benchmarks
  • DeepSWE appears to actually measure what the vibe check measures

2 DeepSWE's Four Major Advances ▶ 0:46

DeepSWE is built by DataCurve.ai and delivers four key innovations over existing public benchmarks:

  1. Contamination-free tasks — Every task is written from scratch, not adapted from existing commits or PRs. No model has seen the solution during pre-training. This is critical because many benchmarks use public GitHub issues and commits that models were likely trained on — so they "already know the answer."
  2. High diversity — Tasks span a broad pool of 91 repositories across 5 languages (TypeScript, Go, Python, JavaScript, Rust). Not just Python, not just the biggest repos.
  3. Real-world complexity — Prompts are half the length of SWE-Bench Pro's, yet solutions require 5.5× more code and 2× more output tokens. This tests whether the model can actually write code, not how well you can explain the problem to it.
  4. Reliable verification — Dramatically reduced false positives and false negatives compared to SWE-Bench Pro.
"If you're anything like me, you're typing 'fix it' and that's it." — DeepSWE tests how real developers actually prompt coding agents.

3 The Leaderboard — GPT 5.5 Dominates ▶ 3:43

The actual leaderboard results are strikingly different from what other benchmarks show:

  • GPT 5.5 (extra high) — absolutely dominating at ~70%
  • GPT 5.4 — second place
  • Opus 4.7 — third, with a 15+ point gap below GPT 5.5
  • Sonnet 4.6 — significantly further behind
  • Gemini 3.5 Flash — 28%
  • Claude Haiku 4.5 — 0% (yes, zero)

This is fundamentally different from other benchmarks where Opus 4.7 and GPT 5.5 appear roughly equivalent. Berman notes that this 15+ point gap actually aligns with what engineers he speaks to are saying: GPT 5.5 is a massive improvement, even over Opus 4.7.

"All the engineers that I've been speaking to praise GPT 5.5 as this massive improvement over previous models and even a massive improvement over Opus 4.7."

4 Prompt Design — Behavior-Focused, Not Prescriptive ▶ 6:24

A key innovation in DeepSWE is how it prompts the models. The prompts are "behavior-focused, short, and free of large interface definition blocks":

  • Instead of: "This code block is wrong, change it to this other implementation"
  • DeepSWE says: "This thing isn't working like I think it should. It should work this other way. Go fix it."
  • Agents must discover where and how to implement the change — testing end-to-end exploration, not just execution of an over-specified task

Berman highlights that this matches the current best practice: "Don't tell the agent how to solve the problem. Tell the agent what you want solved." Describe the behavior you're looking for and let the model solve it any way it likes.

"Don't tell the agent how to solve the problem. Tell the agent what you want solved. Tell them the behavior you're looking for and let the model solve it any which way it likes."

5 Repository Coverage & Contamination Prevention ▶ 7:32

DeepSWE's task pool spans 113 tasks across 91 active open-source repositories in five languages. Selection criteria:

  • Must be public and actively maintained
  • At least 500 GitHub stars
  • Released under a permissive open-source license
  • Languages: TypeScript, JavaScript, Python, Go, and Rust

Crucially, the benchmark tests problem-solving, not recall. Every task is original — the reference solution is written from scratch rather than copied from an existing PR, commit, or public patch. Some tasks are motivated by unresolved GitHub issues, but the fix itself is always new.

Each task ships with three artifacts: the prompt, an executable verifier that grades the result, and a reference solution used during review.

6 Verifier Accuracy — SWE-Bench Pro's Dirty Secret ▶ 8:49

This is perhaps the most damning comparison. DeepSWE's verifiers dramatically outperform SWE-Bench Pro's:

  • False positive rate (verifier accepted a wrong implementation):
    • SWE-Bench Pro: 8.5%
    • DeepSWE: 0.3%
  • False negative rate (verifier rejected a correct implementation):
    • SWE-Bench Pro: 24%
    • DeepSWE: 1.1%

Berman is stunned by the SWE-Bench Pro false negative rate: "I can't believe that happens 24% of the time." The DeepSWE verifiers are implementation-agnostic — they check whether the submitted code implements the requested behavioral change, regardless of the specific implementation strategy.

SWE-Bench Pro's verifier rejects correct solutions 24% of the time. DeepSWE's false negative rate is just 1.1%.

7 Tokens, Wall Clock & Cost Comparison ▶ 11:02

DeepSWE reveals dramatic efficiency differences between models. Using the MiniSuite Agent harness (from the SWE-Bench authors) held fixed across all models:

Output tokens per trial (median):

  • Opus 4.7: 60,000 tokens
  • GPT 5.5: 16,000 tokens (~3.75× more efficient)
  • Gemini 3.5 Flash: 150,000 tokens (most verbose)

Wall clock time per trial:

  • Gemini 3.5 Flash: 15 minutes
  • GPT 5.5: 20 minutes
  • Opus 4.7: 37 minutes

Cost per trial:

  • GPT 5.5: $5.80
  • Gemini 3.5 Flash: ~$5.80 (similar cost, half the score)
  • Opus 4.7: $16 (~3× more expensive)

An interesting observation: within Claude Code (its own harness), Opus 4.7's median tokens drop by ~10,000. Within Codex, GPT 5.5's tokens go up by ~10,000. The harness matters.

GPT 5.5: highest score (~70%), lowest cost ($5.80/trial), fastest among top models (20 min). Opus 4.7: 15+ points lower, 3× the cost ($16/trial), nearly 2× the time (37 min).

8 Score Spread — Why This Benchmark Is More Useful ▶ 11:57

Berman makes a crucial point about benchmark utility: if all models cluster around similar scores, the benchmark isn't useful. You want to see big disparities because they tell you which model is actually better.

  • SWE-Bench Pro: all models within ~30 points of each other — relatively close, hard to differentiate
  • DeepSWE: scores range from 70% (GPT 5.5) all the way down to 0% (Claude Haiku 4.5) — a massive spread that creates clear separation between tiers

This wider distribution of scores makes DeepSWE far more discriminating as a benchmark — it actually separates the strong models from the weak ones.

9 Model Behavioral Insights ▶ 14:12

DeepSWE also reveals fascinating behavioral patterns across model families:

Claude is forgetful with multi-part prompts:

  • Claude configurations missed requirements more than any other family
  • When prompts enumerate parallel behaviors (e.g., "support both sync and async"), Claude often implements the obvious branch and forgets to mirror its changes

Claude is attentive to its environment:

  • When the prompt and repo state don't match, Opus 4.7 often explores recent changes with git log and recovers the gold solution from git history

GPT implements exactly what is asked:

  • GPT 5.5 has the lowest rate of missing stated behaviors of any configuration
  • It reads the prompt and visible repository contracts literally and produces a patch that honors both

Stronger models test their own work:

  • SWE-Bench Pro's prompt actually discourages agents from writing tests — which Berman finds baffling: "Why would you? That's part of giving a valid solution."
  • Without that restriction, models are much more likely to self-verify with their own tests

10 Community Reception & Verdict ▶ 15:57

The developer community has responded positively. Berman highlights Theo (t3.gg) calling it "the first code bench that actually aligns with how it feels to use these models coding."

Berman notes a few caveats and open questions:

  • The benchmark uses a fixed harness (MiniSuite Agent) across all models — but there's an argument that models and their harnesses should be optimized together. Opus 4.7 not being tested with Claude Code could hurt its score.
  • Composer 2.5 is notably missing from the benchmark — Berman believes it's probably the best model for price-to-performance
  • Berman personally hasn't found GPT 5.5 to be the best for his own code, but acknowledges it's what most engineers are saying
"This is the first code bench that actually aligns with how it feels to use these models coding." — Theo (t3.gg)

🎯 Key Takeaways

  1. DeepSWE Aligns with Reality — Unlike existing benchmarks, DeepSWE's results match what engineers on coding Twitter are actually experiencing with these models.
  2. GPT 5.5 Dominates — 15+ point lead over Opus 4.7, at one-third the cost and nearly half the time. The first benchmark to clearly show this separation.
  3. Contamination-Free by Design — All 113 tasks are handcrafted from scratch. No model has seen the solutions during pre-training, unlike benchmarks that pull from public GitHub.
  4. Short Prompts, Hard Solutions — Prompts are half the length of SWE-Bench Pro's, but solutions require 5.5× more code. This tests coding ability, not prompt comprehension.
  5. SWE-Bench Pro's Verifier Is Broken — 8.5% false positives and a shocking 24% false negatives. DeepSWE's verifier achieves 0.3% and 1.1% respectively.
  6. Cost Efficiency Gap Is Enormous — Opus 4.7 costs ~$16/trial vs. GPT 5.5's $5.80, uses 3.75× more tokens, and takes nearly 2× longer — all for a lower score.
  7. Score Spread Matters — SWE-Bench Pro clusters models within ~30 points. DeepSWE spreads them from 0% to 70%, making it far more useful for model selection.
  8. Claude Forgets Multi-Part Requirements — When asked to support parallel behaviors (sync/async, line/block comments), Claude implements one branch and forgets the other.
  9. GPT 5.5 Is the Most Literal Executor — Lowest rate of missing stated behaviors; reads the prompt and repo contracts literally and honors both.
  10. Harness Matters — Opus 4.7's token usage drops in Claude Code; GPT 5.5's rises in Codex. Testing model + harness together may give different results than a fixed scaffold.
  11. Self-Verification Is Natural — Without SWE-Bench Pro's restriction against writing tests, stronger models naturally self-verify their work.
  12. Five Languages, 91 Repos — TypeScript, Go, Python, JavaScript, and Rust across diverse architectures — a much broader proxy for real-world coding than Python-heavy benchmarks.
