1 The Problem Without Worktrees ▶ 0:00

The classic scenario: you're working on a feature, a critical bug report comes in. Without worktrees, you need to stash your progress, switch to main, fix the bug, switch back, pop the stash — losing time and context with every switch.

A worktree is basically a copy of your project folder but with the same Git history. Think of it as opening the same Google Doc in two tabs, each at a different version — same history, but now they're separate and you can edit independently.

2 Why Worktrees Are Exploding Now ▶ 2:00

Git worktrees were created 11 years ago (2015), but Google Trends shows they're 15x more popular now than even in late 2025. The reason: AI agents.

With worktrees, multiple things happen simultaneously:

  • Worktree 1: New authentication feature
  • Worktree 2: Hot-fixing a bug
  • Worktree 3: Reviewing a PR

This is especially critical for AI agents. If you're not running multiple agents in parallel, you're missing out on significant productivity.

3 Why AI Agents Love Worktrees ▶ 3:00

Three key problems that worktrees solve for AI agents:

  • True parallel execution — No more cross-fighting. Without worktrees, Agent A and Agent B might modify the same file, causing confusion: "Why is this file different from when I read it last time?"
  • No context pollution — Switching branches while an agent is working pollutes its context with state that doesn't exist. Worktrees eliminate this entirely.
  • Become an agentic conductor — Each agent gets their own isolated world. Agent A adds a feature, Agent B fixes a bug, both run simultaneously. When done, you review and merge.
This is the same sequential vs. parallel problem solved in computer science in the 1950s. Worktrees bring parallel computing to your Git workflow.

4 Worktrees in Claude Desktop (Easy Mode) ▶ 6:00

The easiest way to use worktrees: Claude Desktop app handles them automatically. Just open two Code sessions pointing to the same project folder — each session gets its own worktree.

David demos creating two sessions: one building a PowerPoint presentation and another designing a Supabase backend architecture, both in the same folder without conflicts.

Downside: the desktop app asks for permissions on every action, which slows you down significantly.

6 Full Live Demo — Multi-Agent Worktree Workflow ▶ 11:00

David walks through a complete workflow with three terminal Claude Code agents:

Setup:

  1. Agent 1 initializes a Git repo, creates an Express app with a /users endpoint, installs dependencies, commits — all in seconds with Opus fast mode
  2. Agent 2 creates two worktrees: feature/authentication and feature/front-end-design
  3. Each agent CDs into its worktree: cd ../front-end-design / cd ../authentication

Parallel execution:

  • Agent 1 (front-end): "Build beautiful front end for Git learning app — interactive single page site with hero section and visual cheat sheet of core Git commands"

  • Both finish independently — Agent 2 in under 58 seconds

Review & merge:

  • Agent 3 (reviewer): Launches in root project, checks all worktrees, reviews both agents' work with sub-agents running in parallel
  • git merge feature/authentication — merges cleanly
  • git merge feature/front-end-design — has conflicts, but Claude Code resolves them automatically
  • Result: a fully working "Git Master" learning app with interactive flip cards for all Git commands

7 Key Git Worktree Commands ▶ 15:00

Quick reference for the essential commands demonstrated:

  • git worktree add ../feature-name feature-branch — create a new worktree
  • git worktree list — show all worktrees and their branches
  • git merge feature/branch-name — merge a worktree's branch back into main
  • git worktree remove ../feature-name — clean up a worktree
  • git worktree prune — remove stale worktree references
