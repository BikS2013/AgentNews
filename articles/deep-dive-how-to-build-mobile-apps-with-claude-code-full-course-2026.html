2 Mobile App Architecture 101 2:35

Before writing a single line of code (or prompt), Nick lays out the fundamental architecture of any mobile application. This conceptual grounding is essential — even when Claude Code generates the code, understanding what you're building helps you direct Claude effectively.

What Every Mobile App Needs

  • A database — Somewhere to store user data, whether local (on-device) or remote (cloud server). Without persistence, your app forgets everything when closed.
  • Read/write access — The ability for the app to retrieve stored data and save new data. This is the CRUD (Create, Read, Update, Delete) foundation.
  • Modification capabilities — Users must be able to change their data: edit a habit name, update a timer setting, delete an entry.
  • A meaningful UI — An interface that makes the database interactions intuitive, beautiful, and accessible. The UI is the user's window into the data layer.
  • Optional: Authentication — User accounts, sign-up/login flows, session management. Needed when data is user-specific and cloud-stored.
  • Optional: API integration — Connecting to third-party services (AI models, payment processors, analytics, push notifications).
  • Optional: AI features — Using language models or other AI services to add intelligent capabilities to the app.

Framework Choice: React Native + Expo

Nick explains why React Native with Expo is the optimal choice for AI-assisted mobile development in 2026:

  • Zero-config setup — No Xcode, no Android Studio, no complex build chains. Expo abstracts all of it away.
  • Cross-platform — One codebase runs on both iOS and Android. Write once, deploy twice.
  • Hot reload on real devices — Change code, see the result on your phone in seconds via Expo Go app.
  • Simplified App Store submission — EAS (Expo Application Services) automates the build, signing, and submission process that used to take days of painful configuration.
  • Claude Code compatibility — React Native + Expo has excellent representation in Claude's training data, meaning Claude generates high-quality, idiomatic code for this stack.
  • JavaScript/TypeScript ecosystem — Massive package ecosystem, tons of community resources, and a language that Claude handles exceptionally well.
Why not Flutter, SwiftUI, or Kotlin? Nick addresses this directly: while those are excellent frameworks, Expo's zero-config approach and Claude's strong React Native knowledge make it the clear winner for AI-assisted development. The goal is shipping apps, not framework mastery.

5 Git & GitHub for Mobile Apps 1:00:38

With App 1 complete, Nick pauses to establish proper version control. This isn't just good practice — it's a requirement for the deployment pipeline that comes later.

Why Version Control Matters for Mobile Apps

  • Track changes over time — See exactly what Claude changed in each iteration. Essential for understanding your codebase.
  • Revert if something breaks — Claude sometimes introduces regressions when fixing one thing. Git lets you roll back instantly.
  • Share with team members — If you're working with others (or hiring a developer to help), Git is the standard collaboration tool.
  • Required for EAS deployment — Expo Application Services pulls from your Git repository to build your app. No Git = no automated deployment.
  • Branching for experiments — Try risky changes on a branch. If they work, merge. If not, delete the branch. Zero risk.

Git Walkthrough

git commit -m "Initial commit: habit tracker app" — Save the snapshot with a descriptive message
Create a new repository on GitHub.com

git push -u origin main — Push your code to GitHub

6 Adding a Database with Supabase 1:04:41

The transition from local-only to cloud-backed is the biggest architectural leap in the course. Nick explains why you need a real database and then introduces Supabase as the ideal solution.

Why Local Storage Isn't Enough

  • Data lives only on one device — Switch phones and everything is gone. No backup, no sync.
  • No multi-user support — Can't have different users with different data on the same app.
  • No server-side logic — Can't send notifications, process data in the background, or enforce business rules.
  • No analytics — Can't understand how users actually use your app without server-side data collection.
  • Limited scalability — Local storage has size limits and no indexing for complex queries.

Why Supabase

Nick makes a strong case at 1:05:20 for Supabase as the backend of choice:

Generous Free Tier 500MB database, 1GB file storage, 50,000 monthly active users. Enough for most indie apps.
PostgreSQL Core Real relational database under the hood. Not a toy — it's the same technology powering Instagram, Spotify, and Netflix.
Built-in Authentication Email/password, social logins (Google, Apple, GitHub), magic links, phone auth — all pre-built and configurable.
Real-time Subscriptions Data changes push to connected clients automatically. Perfect for collaborative or live-updating features.
Row Level Security (RLS) Database-level security policies ensuring users can only access their own data. Critical for multi-user apps.
Claude Knows It Well Supabase has excellent representation in Claude's training data. Claude generates idiomatic Supabase queries, schemas, and auth flows with high accuracy.

Supabase Setup

Full setup walkthrough starting at 1:05:43:

Create a free Supabase account at supabase.com
Create a new project — choose a name, set database password, select region
Grab the API URL and anon key from project settings
Install the Supabase JS client: npm install @supabase/supabase-js
Configure the client in your app with the URL and key
Tell Claude to design the database schema and write the migration SQL
Run the migration in Supabase's SQL editor

Migration Pattern: Local → Cloud

One of the most practical demonstrations: Claude rewrites the data layer from AsyncStorage to Supabase while keeping the UI completely intact. The user experience doesn't change — but the backend is now cloud-powered. This pattern of "swap the backend, keep the frontend" is a powerful architectural principle.

9 Testing & Quality Assurance 2:56:13

Before any app goes to the App Store, it needs thorough testing. Nick's approach is practical, not academic — he focuses on the tests that actually catch real bugs in AI-generated mobile apps.

Testing Checklist

  • Real device testing — Every feature must work on a physical phone, not just an emulator. Touch targets, scroll behavior, and performance can all differ.
  • Database operations end-to-end — Create, read, update, delete. Verify data appears in Supabase dashboard after creating in the app.
  • Authentication flows — Sign up with a new email. Log out. Log back in. Close the app and reopen — session should persist. Test "forgot password" flow.
  • Edge cases:
    • What happens with no internet connection?
    • What do empty states look like (no habits, no sessions)?
    • What happens if the user enters very long text?
    • What if the user rapidly taps a button multiple times?
    • What happens when the app is backgrounded and resumed?
  • Performance — App should feel smooth. No jank, no lag, no white screens between navigation transitions.
  • Both platforms — If targeting both iOS and Android, test on both. Supabase social login behavior can differ.

Pre-Submission Checklist

At 3:00:08, Nick covers what to verify before hitting "Submit":

  • App icon and splash screen are set and look professional
  • App name, description, and keywords are finalized
  • Screenshots are captured for all required device sizes
  • Privacy policy URL is live (required by both stores)
  • All test data is cleared — no debug screens or placeholder content
  • Version number and build number are set correctly
  • Performance is acceptable on older devices (not just your latest phone)
Nick emphasizes: "Test before deploying — every feature should work on a real phone before you consider submission." Apple's review team will find issues you missed, and rejections cost time.

  • App Store Connect — Apple's portal at appstoreconnect.apple.com for managing your apps, viewing analytics, and responding to reviews.
  • EAS CLI installed — npm install -g eas-cli — Expo's command-line tool for building and submitting.

The EAS Build + Submit Pipeline

Starting at 3:47:54:

Configure eas.json — Define build profiles (development, preview, production) with appropriate settings for each stage.
Run eas build --platform ios — EAS builds your iOS binary in the cloud. No Mac required! The build runs on Expo's servers and produces a signed IPA file.
Wait for build completion — Usually 10-30 minutes. You get a URL to track progress.
Set up App Store Connect 3:52:07 — Create your app listing with name, subtitle, description, keywords, screenshots, app icon, privacy policy, and content rating.
Configure API key 3:55:49 — Create an App Store Connect API key and configure it in EAS for automated submission.
Run eas submit --platform ios — Automatically uploads the build to App Store Connect. No manual uploading through Xcode or Transporter.
Submit for review — In App Store Connect, click "Submit for Review". Apple reviews typically take 24-48 hours.

Submission is confirmed at 3:56:12 — Nick shows the "Waiting for Review" status in App Store Connect.

Key revelation: "Submitting to the App Store used to be incredibly painful. With EAS, it's mostly automated." — The combination of Expo + EAS has reduced what used to be a multi-day, error-prone process to a few terminal commands.

Common Rejection Reasons to Avoid

  • Missing privacy policy
  • Broken links or placeholder content
  • App crashes on launch (test on real devices!)
  • Login required but no demo account provided for reviewers
  • Incomplete metadata or misleading screenshots
  • Using private APIs (unlikely with Expo, but worth checking)

11 Google Play Store Submission 3:50:07

The Android path is covered as an alternative (or complement) to iOS. The process is simpler in some ways, more complex in others.

Key Differences from iOS

Cost $25 one-time fee (vs. Apple's $99/year). Much more accessible for indie developers.
Review Process Typically faster than Apple. Less strict guidelines, but still has quality requirements.
Build Output EAS generates an AAB (Android App Bundle) instead of IPA. Same command, different platform flag.
Distribution Can also distribute APKs directly (sideloading), giving more flexibility for testing and beta distribution.

Android Submission Process

Create a Google Play Console account ($25 one-time registration)
Run eas build --platform android to generate the AAB file
Create your app listing in Play Console: title, description, screenshots, content rating, privacy policy
Upload the AAB via eas submit --platform android or manually through Play Console
Complete the content rating questionnaire and data safety section
Submit for review and wait for approval

Nick notes that targeting both platforms simultaneously is the power of React Native + Expo: one codebase, two stores.

12 Post-Launch — App Store Optimization 4:00:10

Getting the app on the store is only the beginning. Nick closes the course with strategies for growing your app post-launch.

Promo Codes

  • Apple gives you promo codes for each app version — use them for early testing, reviews, and influencer outreach
  • Great for getting initial reviews on the store (reviews heavily influence download rates)
  • Can be shared with beta testers as a "thank you" before public launch

App Store Optimization (ASO)

  • Keywords — Research what terms people search for. Include them in your app title, subtitle, and keyword field.
  • Screenshots — Your #1 conversion factor. Show the app's best features with clear, compelling visuals. Use text overlays to explain benefits.
  • Descriptions — Front-load the first 1-3 sentences (that's all most people read). Focus on benefits, not features.
  • App icon — Simple, distinctive, recognizable at small sizes. Avoid text in the icon.
  • Ratings & reviews — Prompt happy users to rate (timing matters — ask after a positive interaction, not on first launch).
  • Localization — Even just translating metadata (title, description, keywords) to other languages can dramatically increase downloads.

User Feedback & Iteration

  • Read every review and respond thoughtfully
  • Track which features users request most frequently
  • Use analytics (built into both App Store Connect and Play Console) to understand usage patterns
  • Iterate with Claude Code — describe the change, test, deploy. The update cycle can be as fast as a few hours.
